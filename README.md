# قيمي: رعاية المتعلمين (متوسطة لبيد بن ربيعة)

أحد أنظمة النواة الرقمية. يعمل على قاعدة النواة (Supabase) ويشارك جلسة الدخول مع بقية الأنظمة بهوية النواة نفسها.
النواة هي المصدر المرجعي للمتعلمين والصفوف والمنسوبين، ولا تُنسخ سجلاتهم هنا. سجلات التعزيز والسلوك تبقى في جداول النظام (`qm_`).

## التشغيل
1. نفّذ `supabase/migrations/0201_qiyami_foundation.sql` في قاعدة النواة (طُبّق فعلاً على قاعدة labeedsch_PC). لا يعدّل أي جدول في النواة.
2. فعّل GitHub Pages: Settings ← Pages ← Source: GitHub Actions. الموقع على `/qiyami/`.
3. من لوحة النواة عيّن وكيل شؤون الطلاب (جدول `qm_staff_roles`، دور `agent`). الموجه الطلابي يُعيَّن مبدئياً من مسماه الوظيفي.

## الأدوار
| الدور | كيف يتحدد | ماذا يرى |
|---|---|---|
| المعلم | أي منسوب فعّال في النواة | تسجيل تعزيز وسلوك، وقائعه هو، سجل التعزيز، الأرصدة، دليل المتعلمين |
| وكيل شؤون الطلاب | `qm_staff_roles.role = 'agent'` | صندوق الوقائع: مراجعة، طلب استكمال، توثيق إجراء، إحالة، إغلاق |
| الموجه الطلابي | `qm_staff_roles.role = 'counselor'` | الحالات المحالة إليه، ملاحظات إرشادية سرية لا يراها المعلم |
| مدير النواة | `is_core_admin()` | قراءة المؤشرات، إلغاء التعزيز، تصحيح الرصيد، إسناد الأدوار |

الحماية على الخادم: الجداول مغلقة بـ RLS، والعمليات عبر دوال `qm_*` تتحقق من الدور. إخفاء عناصر الواجهة وحده لا يكفي ولا يُعتمد عليه.

## المسارات
- **التعزيز**: يُسجَّل مباشرة دون اعتماد، بنقاط أو بدونها. الرصيد يُحسب من دفتر الحركات (`qm_points_ledger`). الإلغاء قيد عكسي موثق ولا حذف.
- **الواقعة السلبية**: معلم ← وكيل شؤون الطلاب ← موجه طلابي عند الحاجة. تُسجَّل «مرصودة» ولا تخصم نقاطاً ولا تُعرض مخالفة مثبتة. الحالات قابلة للتعديل من `qm_incident_statuses`.
- كل إجراء في سجل زمني (`qm_incident_events`) بمستوى ظهور: للمعلم، داخلي، أو سري للموجه. وكل عملية في `qm_audit_logs`.
